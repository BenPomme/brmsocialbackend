## Agent Brief

**Category:** bug
**Summary:** A client session must not approve, edit, or block another shop's avis, including via a foreign avis id on their own URL.

**Current behavior:**
The client thread route checks access to the URL's client, then `handleClientReply` loads the avis by id with no client check. A missing id falls back to another pending 1–3★. An unbound client session (`clientId` null) is allowed through the `session.clientId && mismatch` test. The inbound message row is written before validation.

**Desired behavior:**
A client-role session with no account binding fails closed. Reviews are resolved by authorized account id plus review id, before any message row. An explicit foreign or missing review id is rejected; there is no fallback. Approval is stored against the exact reply version. A later material edit invalidates that version. Publish independently checks account, version, and a still-valid approval. Repeated approval of the same version is idempotent. Ambiguous natural-language OK when several reviews are pending asks which review.

**Key interfaces:**
- Owner decision records: review id, reply version id, actor, decision, timestamp, valid flag
- Status transition and approval insert are one conditional transaction

**Acceptance criteria:**
- [ ] A cannot view, approve, edit, or block B's review through A's own URL
- [ ] Rejection creates no misleading message/action record
- [ ] An unbound client session fails closed
- [ ] A stale approval cannot authorize an edited reply
- [ ] A repeated approval is idempotent
- [ ] An explicit foreign or missing review id never approves a fallback review

**Out of scope:**
- Live Google publication
- Operator checklist UX beyond the publish gate
