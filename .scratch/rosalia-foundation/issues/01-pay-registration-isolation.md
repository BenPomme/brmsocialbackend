# 01: Isolate public registration from existing Paid Accounts

**Category:** bug
**Status:** resolved
**Blocked by:** None (can start immediately)

> *This was generated by AI during triage.*

## Agent Brief

**Category:** bug
**Summary:** Anonymous `/pay` registration must never edit an existing shop, even when email or a guessed client id matches.

**Current behavior:**
Public register, checkout, and trial resolve a client by supplied id or by email. Omitted billing fields are written as null, so a second signup can overwrite name, WhatsApp, and fiscal data on a Paid Account that happens to share an email.

**Desired behavior:**
A public registration always creates a new draft shop (or continues the same draft via an opaque capability). Email, phone, and card may be shared across Paid Accounts and are not merge keys. A body `clientId` is never authority. Updates use PATCH semantics: omitted fields stay as they are. The same registration request retried with the same idempotency key does not create a second shop. A forged, expired, or mismatched capability is rejected before any write.

**Key interfaces:**
- Public pay continuation is authorized by a short-lived random capability whose hash is stored, not by client id in the JSON body
- Authenticated membership (session bound to that Paid Account) may patch that account; an unbound or other-account session may not
- Register, checkout, and trial share this boundary

**Acceptance criteria:**
- [ ] Anonymous creation with an existing email creates a separate draft and never edits the existing shop
- [ ] Anonymous and unrelated-account updates using an existing client id are rejected before any write
- [ ] An authorized update changes only submitted fields
- [ ] Two shops with the same email and phone remain separate through registration, checkout, and fulfillment
- [ ] Retrying the same registration request does not create a duplicate
- [ ] A forged, expired, or wrong-registration capability is rejected

**Out of scope:**
- Recurring Stripe Billing
- File 02 conversation tools
- Changing public marketing copy in the website repo
