## Agent Brief

**Category:** bug
**Summary:** Rosalía and the admin inbox must work from the newest messages, not the oldest page, and must answer the triggering inbound event.

**Current behavior:**
History is `orderBy createdAt asc, take 80` (admin: 40). The latest inbound is inferred from that oldest window. An 81-message thread with STOP last is processed as an old hello.

**Desired behavior:**
Fetch newest first with a stable second sort key, then reverse for chronological context. The worker receives the triggering inbound id; it does not infer the event from a history page. Channel-window decisions use the real last customer-message time, not job retry time. Admin history shows the newest page and can page backward. Latest inbound, latest outbound, and unsent draft are loaded separately. Processing is serialized per conversation so a newer message is not overwritten by an older worker.

**Key interfaces:**
- Inbound event id travels with the Rosalía job/decision
- Draft payload records which inbound it answers

**Acceptance criteria:**
- [ ] The latest inbound is processed in 81-, 100- and 1,000-message threads
- [ ] STOP at message 81 suppresses later marketing effects immediately
- [ ] Equal timestamps produce stable ordering
- [ ] Admin history shows the newest messages and can page backward
- [ ] Two messages arriving together do not swap replies or apply an approval to the wrong event

**Out of scope:**
- Dropping the ten-minute session gap (file 02 memory work)
- Building a 240-scenario eval set
